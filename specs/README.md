# Спецификации проверок

Спецификация — файл YAML с определениями проверки: вопрос, набор, меры и правило прохождения, записанные **до** расчёта;
результат и вывод дописываются в конец. Расчёт — скрипт из [`scripts/`](../scripts/), данные — в приватном `longevity-kg`
(реестр данных — `longevity-kg/DATA.md`). Спецификации не удаляются и не переписываются задним числом: это запись того,
что и почему было решено.

Папки — по этапам системы (как в [`docs/system/steps.md`](../docs/system/steps.md)), статус — в таблицах ниже, поэтому
при смене статуса файл не переезжает. Статусы:

- **в работе** — по ней идёт текущая работа: бенчмарк этапа, проверка с назначенным прогоном или план, ещё не выполненный;
- **принято** — правило из неё действует в текущем методе (v3.10), см. [мануал](../docs/method-v3-manual.md);
- **история** — проверка выполнена, правило принято позже другой версией или отклонено; на ней стоит число или решение в мануале;
- **заморожено** — оценки, сделанные до появления исходов; не меняется никогда, сверяется по хэшу;
- **данные** — как получены метки исходов и наборы гипотез; на них стоят все проверки по исходам;
- **v2, оставлено под v3** — проверка всей системы, написанная для метода v2; оставлена, чтобы перезапустить под v3 (см. [бэклог](../docs/backlog.md));
- **v2** — метод v2; оставлено как запись решений.

Прогон, привязанный к спецификации, хранит в метаданных её хэш, коммит и путь на момент коммита
([`hyparena/prespec.py`](../hyparena/prespec.py)); проверка читает файл из того коммита, поэтому перенос файлов по папкам
(2026-11-14) старые отметки не ломает.
