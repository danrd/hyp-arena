Приватные данные прохода (текст, карточки) — `longevity-kg/hypothesis_sources/prospective/walkthrough_H49/`.

Гипотеза: приседания у пожилых с пре-саркопенией (Tzu Chi University), реестр с 2026-07-24, набор идёт, завершение
2026-12-31. Дата среза T = 2026-11-06 (оценки проспективного пула закреплены хешем).

## Этап 2. Карточка

**Как устроен запрос к модели** (`hyparena/prompts/normalize_card/v10.j2`, Gemini 3.5 Flash, температура 0, один вызов):

- **Передаём:** только текст гипотезы (для реестра — строки «Поле: значение»); закрытый список отношений; список признаков
  старения. Не передаём дату T, литературу и другие гипотезы.
- **Специфицируем** (правила по каждому полю): тип гипотезы; одна фраза простыми словами; PICO (популяция, вмешательство,
  контроль, исход; «unknown» для всего, чего нет в тексте); 1–8 атомарных утверждений-звеньев: субъект, отношение из
  закрытого списка, объект, уточнения (вид, пол, возраст, доза, ткань, мера, болезнь — только названные в тексте), роль,
  место в цепочке (доставка → действие на мишень → путь → эффект → исход), дословная опора в тексте; рёбра «требует»;
  заявленная новизна; роль ИИ с дословной фразой; заявленный эксперимент (система, конечная точка, длительность, дизайн,
  контроль, плановая выборка, первичный исход); альтернативы, названные самим текстом; критерии решения; риски.
- **Ключевые правила:** записывать только то, что текст утверждает, без фона и знаний модели; шаг механизма — только если
  текст сам его называет (в том числе «тем самым», «потому что», осторожно сформулированный); параллельные исходы — не
  цепочка; для «улучшает здоровье» объект — организм, а что улучшается — в уточнении «мера».
- **Даём:** два разобранных примера других гипотез (только формат) и пустой JSON-скелет ответа.
- **Код потом:** проверяет схему и дословность опор (до трёх раундов; утверждение без дословной опоры выбрасывается);
  при отношении исхода «other» — один повтор с подсказкой ближайших отношений; для текста реестра заполняет конечную точку
  и популяцию из полей.

**Что получилось у H49.**

| | Первый разбор (пул, 2026-11-06) | Второй разбор (текст с полями дизайна, 2026-11-11) |
|---|---|---|
| Звенья | 3, все «исход»: SPPB (главный), состав тела, пре-саркопения | 5: те же три + промежуточные эффекты «мышечная масса» и «сила ног», через них — пре-саркопения |
| Механизм | не выписан (флаг) | выписан, но ведёт к пре-саркопении, а не к главному исходу SPPB — так и сказано в тексте |
| Эксперимент | всё «неизвестно» | РКИ, обычный уход, 80 |
| Стоимость | — | 4 298 + 1 072 токена, около 0.004 USD |

| Вопрос | Ответ / решение |
|---|---|
| Тройка «приседания — улучшают здоровье — человек» бессмысленна | Это правило шаблона (объект — организм, суть — в «мере»); ошибка в показе. **Решение:** в отчёте для таких отношений плашка объекта показывает меру и организм в скобках: «улучшает → физическая работоспособность (человек)». | Почему первый разбор не выписал механизм, хотя фраза «тем самым…» была и тогда? | Разброс модели при температуре 0. **Решение:** карточка — объединение двух независимых разборов (мануал, раздел 3; `normalize_union`, `normalize_runs: 2`). На H49 согласие разборов (общие звенья / все) — 0.6 |
| Звено «сила ног» записано как «улучшает здоровье — человек (сила ног)», а не «повышает — силу ног» | Открыто. Правило шаблона направляет «улучшает функцию» в «improves_healthspan_in»; для промежуточного эффекта естественнее «promotes». Кандидат в правку шаблона v11 |
| Механизм не подкрепляет главный исход (SPPB) | Открыто. Так записано в тексте; вопрос — к этапу 5 (места цепочки и параллельные исходы) |

### Этап 2, вопросы пользователя 2026-11-11: что проверяет код, как заданы правила, откуда звенья механизма

**Что проверяет код** (`hyparena/card/normalizer.py` `_problems`, `hyparena/card/rules.py` `validate_card`):
- схема: JSON разбирается в модель карточки; отношение, роль, тип звена, тип гипотезы, тип ребра, конечная точка, признак
  старения — из закрытых списков (`models.py`); значение вне списка — ошибка, модель получает свой ответ и список ошибок и
  отвечает заново (до трёх раз); исключение — поля эксперимента: вне списка становятся «неизвестно»;
- структура: ровно одно главное утверждение; не больше 8 утверждений; id уникальны; рёбра ссылаются на существующие
  утверждения; рёбра «требует» без циклов; у отношения «other» есть пояснение; правила наследования вида из PICO;
  «в основном X, а не Y» оформлено парой с отвергнутой альтернативой;
- дословность: у каждого утверждения есть опора, и она — дословный фрагмент текста (без учёта пробелов и регистра);
  утверждение без такой опоры выбрасывается;
- поправки кодом: пол «любой» по словам текста, единая запись дозы и возраста, конечная точка и популяция из полей реестра,
  роль ИИ «нет» без дословной фразы; карточка без вмешательства или исхода к оценке не допускается.

**Чего код не проверяет:** верно ли выбран тип звена и отношение (c4 «сила ног» как «улучшает здоровье»), полон ли
механизм, действительно ли опора говорит о причине, а не просто содержит слова. Это задано только словами в промпте и
проверяется выборочно: устойчивость к перефразированию (L1.8b: тройки 1.00, контекст 0.80 при пороге 0.82 — не пройдено),
полнота механизма против ручной разметки (6 из 8 на свежих 44 текстах — пройдено; 7 из 12 на калибровочных 30 — не пройдено).

**Откуда звенья механизма.** Только из шагов, которые текст называет сам (гипотеза оценивается как написана; модель —
разборщик, не учёный). Типы звеньев (доставка → действие на мишень → путь → промежуточный эффект → исход) повторяют путь
лекарства к клинике; выбраны в спецификации v3 (2026-11-03) после того, как v2 — набор несвязанных утверждений — не различал
гипотезы (AUC 0.46 на 30 испытаниях). Задачи типизации: разные шкалы веса до исхода и на исходе, сопоставление со звеньями
графа знаний по закрытым отношениям, поиск слабого звена.

**Что доказано, а что нет.** Сравнения «типизированная цепочка против других разложений» не было. Рост v2 → v3 (0.46 → около
0.59 по исходам) смешивает много изменений сразу; на реестрах механизм выписан редко (10 из 30 карточек калибровки), и балл
держится в основном на звене исхода; гипотезы с выписанным механизмом из 3 и более мест на калибровке все оказались
нулевыми (`specs/argon-layers-2026-11-08.yaml`). То есть предсказательная польза цепочки на реестрах не показана; её
польза — объяснительная (где слабое место) и для созданных и улучшенных гипотез.

**Как проверить, что этот подход лучше** — решение 2026-11-11: спецификация `specs/mechanism-chain-comparison-2026-11-11.yaml` (только исход / свободная цепочка без типов / наша типизированная; дополнение механизма знаниями не проверяем — гипотеза оценивается как написана).

**Типы звеньев — на что опираемся** (проверено 2026-11-11 по PubMed): «три опоры» Pfizer (Morgan et al., Drug Discov Today
2012;17:419-24: экспозиция в месте действия → связывание с мишенью → фармакологическая активность) и путь неблагоприятного
исхода AOP (Ankley et al., Environ Toxicol Chem 2010;29:730-41; руководство ОЭСР: молекулярное событие → ключевые события →
исход, вес доказательств на каждую связь). Это наша адаптация, не стандартная онтология; записано в разделе 3 мануала.
На схеме у этапов теперь строка «Основа» со ссылками (PICO, «три опоры», AOP, GRADE, strong inference, BEST, SMAA, АСПИД);
этапы без неё — наша разработка (поиск, чтение, новизна, улучшения, сквозная проверка).
