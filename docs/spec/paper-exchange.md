# Передача каркасов статей между прогоном, чатом и longevity-kg

Единица обмена — один PMID и один снимок статьи. Задание `paper-task/1` содержит текст, область чтения, метаданные, SHA-256 текста, инструкцию и JSON Schema. `task_id` — хеш всего задания, включая инструкцию. Ответ отдельной модели привязан к этому ID. Одна статья может иметь несколько снимков, разборов и независимых оценок. Приватные задания, ответы, цитаты и база остаются на стороне longevity-kg.

## После каждого прогона оценки гипотез

1. Сохраните исходные архивы и выполните экспорт по [инструкции бенчмарка](../validation/whole-system.md). Из корня **longevity-kg** сформируйте очередь по манифесту завершённых испытаний. В примерах `python` — интерпретатор с зависимостями обоих проектов.

```powershell
$export = '../hyp-arena/runs/codex-benchmark-v2/kg-export/manifest.json'
$q = 'build/run-paper-queue'
python -m tools.skeleton.exchange prepare $export --run-export --out $q --db build/skeleton.db
```

2. Откройте `$q/manifest.json`. Каждая запись хранит PMID, хеш снимка, область чтения и ссылки на вызовы ридера с хешем архива и датой отсечения. Команда обходит распознанные блоки статей во всех сохранённых вызовах verify_claim, включая статьи без находки. Повторы одного задания объединяются. Отдельно проверьте `unparsed_reader_calls` и списки pending/without_archive исходного экспорта. Отсутствие сохранённого текста означает пробел в покрытии. Поисковая выдача сама по себе не доказывает, что ридер видел текст.
3. При `reuse` возьмите указанный `extraction_id`; при `select` сравните версии и зафиксируйте выбранную или оставьте неопределённость. Команда `get` ниже возвращает готовый каркас. При `annotate` передайте файл `task_file` разметчику; `retracted` исключается из очереди. При необходимости ограничьте модель опцией `--model`. Повторите подготовку после импорта и сохраните итоговый манифест вместе с прогоном. Для воспроизведения прогноза сохраните в его материалах выбранный ID и дату отсечения; проверьте дату публикации и доступность конкретной версии текста на эту дату. Результат поздней публикации нельзя использовать для исторической оценки.
4. Backfill из ответов ридера продолжает хранить частичные наблюдения. Наличие записи для PMID не заменяет совпадение текста, области чтения и совместимой версии разбора. В очереди допускаются независимые разборы штатного парсера текущей версии и текущей версии чат-задания. Найденный каркас можно передать этапу сопоставления; действующий ридер v21 сам этот манифест не читает.

## Одно задание в любой чат

В манифесте `other_versions` показывает также независимые разборы того же PMID на других снимках или с другими настройками. В том числе можно найти полный текст, когда в архиве прогона была только аннотация, и открыть его по ID. Использование такого разбора меняет вход оценки: сохраните это как отдельный вариант прогона.

Для отдельного сохранённого снимка выполните из longevity-kg:

```powershell
python -m tools.skeleton.exchange prepare build/text_cache/32785021.input.json --out build/chat-pilot
```

Для **полной статьи** подготовьте UTF-8 файл: первая строка — заголовок, далее аннотация, пустая строка, отдельная строка `Full text:` и весь доступный основной текст. Сохраняйте заголовки разделов, подписи, строки и столбцы таблиц и сноски. Зафиксируйте в тексте, какие приложения включены. Передавайте фактический URL и лицензию доступного для такого использования источника. Для сокращённого снимка используйте штатный `*.input.json` с областью `abstract+results_excerpt`.

```powershell
python -m tools.skeleton.exchange prepare $articleFile --full-pmid $pmid --source-url $articleUrl --license $articleLicense --out build/chat-pilot
```

Прикрепите **один** `*.task.json` и напишите: «Разметь всю статью из приложенного задания. Верни один JSON с task_id, coverage и skeleton согласно инструкции внутри файла. Если прочитана только часть, поставь partial». Не прикладывайте старые ответы или оцениваемую гипотезу при независимой разметке. Сохраните оригинальный ответ в приватной папке как UTF-8 JSON без Markdown-ограждений. Запишите фактическую модель/версию, которую показывает чат.

```powershell
python -m tools.skeleton.exchange receive $taskFile $replyFile --model $modelId
python -m tools.skeleton.exchange receive $taskFile $replyFile --model $modelId --apply --db build/skeleton.db
python -m tools.skeleton.exchange get $extractionId --db build/skeleton.db
```

Первая команда проверяет ответ без записи в базу. Проверьте журнал очищенных полей, соответствие чисел группам и полноту охвата. Если проверка удалила находку, исправьте ответ и повторите. Вторая команда добавляет версию и печатает её ID. Повторная загрузка того же ответа по тому же заданию и с той же моделью возвращает прежний ID. Исправленный ответ становится новой версией. Сохраняйте исходную пару «задание — ответ» и итоговые ID. Полный охват, заявленный моделью, требует содержательной проверки.

## Удалённое чтение через MCP

Предлагаемый первый интерфейс — две операции только для чтения: поиск версий по PMID, хешу текста и области чтения с фильтром совместимости; получение каркаса по неизменяемому extraction_id. При нескольких версиях вернуть список с происхождением; выбор сохранить в прогоне. Для удалённого поиска по одному PMID сначала возвращать каталог доступных снимков с датами и типом текста. Сервер должен проверять права на приватный корпус; включать текст статьи в ответ только по отдельному разрешённому запросу. Публикацию результатов разметки оставить явной операцией после проверки. Локальные prepare/get уже позволяют проверить этот рабочий процесс до развёртывания сервера.
