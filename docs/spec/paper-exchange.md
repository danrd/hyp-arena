# Полнотекстовая разметка статей в longevity-kg

Команда выбирает статьи для отдельного разбора из общего перечня публикаций. Перечень пополняется по [досье прогонов](../method/dossier-instructions-draft.md). Ниже описаны инструменты для работы с выбранными статьями в приватном longevity-kg.

## Подключение графа

Из корня **longevity-kg**, в окружении с зависимостями каркаса, установите дополнительный пакет `mcp>=1.12,<2`. Для клиента с локальным stdio настройте команду:

```powershell
python -m tools.skeleton.graph_mcp --db build/skeleton.db --full-text-dir build/full_text --inbox build/graph-proposals
```

Задайте этому процессу рабочий каталог longevity-kg и путь к нужному Python. Один сервер обслуживает поиск по списку PMID, получение версии, выдачу полной статьи, отправку поправки и приём законченного разбора. Поправки пишутся в приватную очередь с проверкой цитаты и исходной версии. Завершённый независимый разбор проходит проверку схемы и цитат перед добавлением в базу. При замечаниях возвращается журнал. Проверка не удостоверяет научную интерпретацию или полноту. Доступ к серверу включает чтение приватных данных и эти две операции записи. Для облачного чата нужен отдельно подключённый совместимый сервис с авторизацией; локальный процесс сам по себе доступа такому чату не даёт.

## Подготовить источник один раз

Реестр хранит полный текст под `build/full_text/<PMID>.input.json`. Для открытой статьи из PMC возьмите JATS XML и выполните:

```powershell
python -m tools.skeleton.stage_full_text $xmlFile $pmid
```

Проверяются PMID и открытая лицензия. В снимок входят текст основного корпуса JATS, текстовые строки таблиц, доступные подписи и сноски. Изображения и отдельные приложения в него не входят. Обновлённую редакцию можно поместить в отдельный реестр через `--out`. Подключайте этот реестр для соответствующего прогона. Можно также подготовить задание непосредственно из своего UTF-8 снимка: заголовок, аннотация, пустая строка, отдельная строка `Full text:`, полный основной текст. Передайте `prepare $articleFile --full-pmid $pmid --source-url $articleUrl --license $articleLicense --out $queue`.

## Отдельная пакетная разметка по экспорту прогона

1. После [экспорта прогона](../validation/whole-system.md) из корня longevity-kg выполните:

```powershell
python -m tools.skeleton.exchange prepare ../hyp-arena/runs/codex-benchmark-v2/kg-export/manifest.json --run-export --out build/run-paper-queue
```

2. Откройте `manifest.json` очереди. При `reuse` возьмите готовый ID, при `select` выберите совместимую версию. `select_full_text` означает, что в графе есть полный разбор того же PMID, но его редакцию нужно сверить с задачей. При `needs_full_text` добавьте источник в реестр и повторите команду. При `annotate` прикрепите указанный `task_file` в отдельный чат: «Разметь весь приложенный текст по инструкции в файле и верни один JSON с task_id, coverage и skeleton». Задания формируются только по полным статьям. В источниках очереди сохранены хеш фактического входа ридера, вызов и дата отсечения. Проверьте `unparsed_reader_calls` и незавершённые архивы исходного экспорта.
3. Поле `delivery` задания указывает каталог в приватном longevity-kg: `reviews/paper-annotations/<PMID>/`. Создайте его при первом сохранении. Имя файла — `<task_id>.<модель>.<номер>.reply.json` (номер 01, 02 и далее, без перезаписи). Чат без доступа к репозиторию отдаёт файл для скачивания или JSON; сохраните его в этот каталог в UTF-8 и передайте путь как `$replyFile`. Проверьте журнал очищенных полей, затем импортируйте версию и сохраните ID в материалах полнотекстовой разметки:

```powershell
python -m tools.skeleton.exchange receive $taskFile $replyFile --model $modelId
python -m tools.skeleton.exchange receive $taskFile $replyFile --model $modelId --apply
python -m tools.skeleton.exchange get $extractionId
```

Старые задания и ответы по аннотациям остаются читаемыми. Полнота относится к предъявленному снимку. При частичной проверке для одного звена отправляйте наблюдение с цитатой в очередь поправок. Несколько версий статьи сохраняют общий PMID. При выборе между ними фиксируйте ID, хеш и доступность редакции на дату T.
