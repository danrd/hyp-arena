# Метод v3: цепочка механизма, три оси и запас для эволюции (спецификация, черновик 2026-11-03)

Основание: калибровка метода v2 на 30 испытаниях вне бенчмарка (`specs/calibration-step3-2026-11-02.yaml`, AUC 0.46) и два
бумажных прогона (`docs/spec/mechanism-chain-draft.md`). Решения пользователя (2026-11-02, 2026-11-03):

- в основе оценки механизм: ключевые звенья не опровергаются текущими данными, и механизм способен сильно повлиять на вопрос;
- найденные источники работают двояко: повышают обоснованность звеньев, но гипотеза, проверенная целиком, мало что добавит;
- новизна меряется через альтернативы: что решающий эксперимент позволит отсечь при любом исходе; с учётом реализуемости;
- величина эффекта и число участников важны; обзоры учитываются, но весят меньше первичных исследований;
- альтернативы перечисляет модель (позже — граф знаний); оценивается эксперимент, заявленный в тексте;
- эволюция: перспективная, но недоработанная гипотеза не отсекается; пространство для улучшения — отдельный выход;
- исход конкретного испытания не предсказывается и не является целью; по исходам проверяется только ось правдоподобия.

Что остаётся из v2 без изменений: срез литературы по дате T, поиск запросами модели с лёгким фильтром и расширением по
цитированиям (`hyparena/card/search.py`), градуированный допуск соседней популяции и класса вмешательства, проверка цитат на
дословность, замороженные карточки, температура 0, запись модели, которая фактически ответила.

## 1. Карточка v3

Изменения относительно `hyparena/card/models.py` (v2):

| Что | v2 | v3 |
|---|---|---|
| Утверждения | `claims` с ролями premise / mechanism / analog / outcome / translation | то же плюс **звено цепочки** `link`: `delivery` (вмешательство выполнено и дошло), `engagement` (действие на мишень), `pathway` (путь), `effect` (промежуточный эффект), `outcome` (исход); порядок задают рёбра `edges` (`supports_if_true`) |
| Механизм | нормализатор выделяет его редко (3 утверждения на 27 карточек калибровки) | если в тексте есть обоснование, нормализатор **обязан** записать цепочку от вмешательства до исхода; пропущенное звено — пометка «достроить механизм», не ошибка |
| Признак старения | `Entity.hallmark`, почти не заполняется | заполняется у звеньев `engagement`, `pathway`, `effect`, если звено относится к признаку старения (список `Hallmark`) |
| Популяция | часто теряется («human») | для текстов реестров код берёт её из полей реестра (состояния, критерии включения); нормализатор сохраняет уточнения («жильцы домов престарелых») |
| Альтернативы | `declared_alternatives` — только названные в тексте | плюс **альтернативы, предложенные моделью** (отдельный шаг, раздел 4); у каждой — ссылки на опору |
| Решающий эксперимент | система, исход, класс длительности | плюс дизайн (`rct`, `cluster_rct`, `single_arm`, `pilot`, `observational`), контроль (`placebo`, `active`, `usual_care`, `none`), планируемое число участников, первичный исход; для реестров код заполняет по полям реестра |
| Пробы на животных | `an1`, `an2` для любой гипотезы о людях (половина чтения калибровки — 973 статьи — дала одну запись) | только для вмешательств-веществ, генов и диет; для программ, процедур и устройств — нет |

## 2. Извлечение v3 (запись доказательства)

Новые поля `EvidenceRecord`, модель заполняет их **по всей аннотации**, а не по одной фразе:

| Поле | Значения | Проверка кодом |
|---|---|---|
| `design` | `rct`, `non_randomised`, `observational`, `animal`, `cells`, `review`, `meta_analysis`, `other` | — |
| `n_total` | целое или пусто | `n_quote` (фраза с числом) дословно в аннотации |
| `comparison` | `between_groups`, `within_group`, `none` | — |
| `effect_reported` | как в статье («+2.4 kg», «RR 0.79 (0.65–0.96)») | дословно в аннотации |
| `effect_class` | `none`, `small`, `medium`, `large`, `unclear` | код пересчитывает из интервала или p, где можно |
| `reports_trial` | для обзора: пересказывает ли фраза результат конкретного испытания (TRUST в обзоре 2018 года) | — |

Обзор, пересказывающий конкретное испытание, засчитывается как запись этого испытания (с пометкой `derived_from`), а не как
фон. Общий вывод обзора засчитывается как обзор с пониженным весом. Пример, ради которого это правило: в v2 пересказ большого
нулевого РКИ TRUST был выброшен как фон, а засчитан маленький пилот «до и после» в другой популяции.

## 3. Сила звена

**Принцип весов (решение пользователя, 2026-11-03):** где у признака k различимых упорядоченных уровней, уровень i получает вес
i/k — это прямо следует из числа уровней и не требует отдельного обоснования. От равных шагов отходим только если калибровка
покажет, что они что-то ломают (раздел 9.3); каждое такое отступление записывается здесь с датой и причиной.

Вес записи: `w = дизайн × точность × эффект × сравнение × контекст`, каждый множитель — уровень своей шкалы:

| Множитель | Уровни (от низшего к высшему) | Веса |
|---|---|---|
| дизайн (для утверждений о людях) | клетки, животные, обсервационное, обзор, нерандомизированное, метаанализ, РКИ | 1/7 … 7/7 |
| дизайн (для утверждений о животных) | клетки, обзор, животные (= первичное исследование) | 1/3, 2/3, 1 |
| точность (число участников) | неизвестно или < 30, 30–99, 100–299, ≥ 300 | 1/4 … 4/4 |
| эффект | нет, малый, средний, большой (неясный — средний уровень шкалы, 0.5) | 1/4 … 4/4 |
| сравнение | нет сравнения, внутри группы, между группами | 1/3, 2/3, 1 |
| контекст | тот же класс вмешательства, соседняя популяция или вид, точное совпадение | 1/3, 2/3, 1 |

Запись «нет эффекта» из сравнения между группами — запись «против» с весом по тем же шкалам (эффект для неё — высший уровень:
чёткий нулевой результат весит как чёткий положительный).

Сила звена — уровень шкалы из 6: опровергнуто, спорно, не проверено, слабо, умеренно, сильно → 1/6 … 6/6. Уровень ставится
по взвешенным «за» и «против» (суммы весов, число независимых источников); границы уровней — в коде, рядом с правилами, и
проверяются по примерам. Звено без записей — «не проверено», 3/6.

**Сильное опровержение** (ворота) — правило, а не вес: есть запись «против» высшего уровня дизайна и сравнения (РКИ или
метаанализ, между группами) в нужной популяции, и нет записи «за» того же уровня. Только это отсекает гипотезу.

## 4. Альтернативы и информативность

Отдельный шаг (один вызов модели на гипотезу) по тексту гипотезы и найденной литературе:

1. Модель перечисляет до 5 альтернатив — конкурирующих объяснений того же явления — в форме утверждений карточки.
2. Каждая альтернатива проверяется тем же проверяющим, что и звенья: её обоснованность `a` — сила, как в разделе 3. **Без
   записей `a = 0`**: придуманная альтернатива ничего не добавляет.
3. Для заявленного эксперимента модель заполняет таблицу: что происходит с альтернативой при положительном и при отрицательном
   исходе (отсекается / ослабляется / без изменений). Код переводит в `d`: 1 — отсекается при одном из исходов, 0.5 —
   ослабляется, 0 — без изменений (3 уровня). Код проверяет согласованность (альтернатива не может отсекаться при обоих
   исходах).
4. **Информативность** `I = min(1, Σ a·d / 1.5)`; нормировка 1.5 — не уровень шкалы, а потолок («полтора хорошо обоснованных
   альтернативы отсечены — максимум»), проверяется на чувствительность.

## 5. Оси, ворота, итог

- **Правдоподобие** `P = Π S` по звеньям цепочки, включая доставку. Длинная непроверенная цепочка получает низкий балл сама
  (четыре непроверенных звена: (1/2)⁴ ≈ 0.06 против трёх умеренных: (5/6)³ ≈ 0.58).
- **Размах** `W` — шкала из 3 уровней, только по звеньям не ниже «слабо»: одно состояние или обстановка 1/3; орган или система
  2/3; признак старения 1. Заявленный, но не подтверждённый размах не засчитывается (1/3).
- **Информативность** `I` — раздел 4.
- **Перспективность** `V = P × W × I`. Реализуемость (цена и срок решающего эксперимента, показатели `cost`, `time` v2) —
  отдельный уровень профиля, не множитель.
- Ранжирование — по `V` заявленной гипотезы; под профилями АСПИД — по трём осям с реализуемостью, как в v2.

### Ворота и пометки (эволюция)

| Ситуация | Последствие |
|---|---|
| ключевое звено сильно опровергнуто (раздел 3) | **отсечение** |
| звено не проверено | `S = 0.3`, `P` ниже |
| звено подтверждено в соседней популяции или виде | вес записи ×0.6 |
| опровержение слабыми данными | звено «спорно» |
| заявленный эксперимент слабый | `I` ниже + «улучшить эксперимент» |
| механизм не назван или неполон | «достроить механизм» |
| альтернативы без опоры | `I` = 0 + «назвать альтернативы с опорой» |

### Выход метода по каждой гипотезе

`V`, `P`, `W`, `I`; самое слабое звено и чего ему не хватает; **запас по эксперименту** — `V`, если бы эксперимент отсекал все
перечисленные альтернативы (`d = 1`); пометки из таблицы выше; все записи с цитатами, числами и весами. Запас и пометки — вход
для эволюции.

## 6. Защиты от раздутых гипотез (по построению)

1. Произведение по звеньям и непроверенное звено ниже любого подтверждённого: длинная цепочка без опоры получает низкий `P`.
2. Альтернатива без опоры весит 0: информативность не раздуть, придумывая альтернативы.
3. Размах только по подтверждённым звеньям: заявление «это касается всего старения» без опоры даёт 0.2.

Проверка защит — набор специально раздутых гипотез (раздел 7), которые должны оказаться внизу. В бумажном прогоне придуманная
«теломераза» опустилась с V = 0.45 (правила раунда 1) до 0.001.

## 7. Проверка

| Что | Как | Цена |
|---|---|---|
| Извлечение чисел и дизайна | эталон 15–20 пар «утверждение — статья» с числами, размеченный вручную (первая попытка с Jules не удалась: поля пустые); полнота и точность по `n_total`, `design`, `comparison`, `effect_class` | бесплатно |
| Альтернативы | на 6 примерах бумажного прогона: совпадают ли предложенные моделью альтернативы с ручными, есть ли у них опора | ~$0.1 |
| Правдоподобие `P` | AUC `P` против исходов: сначала на 30 калибровочных точках (уже использованы для отладки — ориентир), затем на свежей выборке испытаний 2023–2026, зарегистрированных задним числом (порог записывается до прогона), затем бенчмарк Б1 | ~$1 калибровка, ~$1–2 свежая выборка, ~$10 бенчмарк |
| Защиты | 5–10 раздутых гипотез (длинные непроверенные цепочки, огромный заявленный размах): все в нижней четверти | ~$0.2 |
| Чувствительность весов | каждый ключевой вес ±50% (раздел 9.3): устойчивость порядка и состава отсечения | бесплатно |
| Размах и перспективность | бумажные примеры; ориентир «пошло ли поле дальше» — сколько испытаний на тот же механизм (мишень, признак старения) зарегистрировано после T (CT.gov, бесплатно) | бесплатно |

Исход испытания не проверяет `I`, `W` и `V` — и не должен (решение пользователя).

## 9. Дополнения (2026-11-03, по развёрнутому примеру с левотироксином)

### 9.1. Первичная статья за обзором

Если обзор пересказывает результат конкретного испытания (`reports_trial`), поиск достаёт первичную статью этого испытания:
по названию испытания или ссылке из обзора, через расширение по цитированиям (ссылки обзора), с тем же срезом по дате T.
Вес считается по первичной статье (её дизайн, n, эффект); запись из обзора остаётся как указатель. Если первичная статья не
найдена, запись из обзора весит как РКИ с неизвестным n (точность 0.3) и получает пометку «найти первичный отчёт».
Пример: пересказ испытания TRUST в обзоре 2018 года весит 0.30 «против»; с первичной статьёй (несколько сотен участников)
— около 1.0, и гипотеза о левотироксине отсекается воротами. Решение об отсечении не должно зависеть от того, попался ли
обзор или первичная статья.

### 9.2. Учебниковые звенья

Звено, которое известно всем, но которое никто не ищет (левотироксин нормализует ТТГ), по общему правилу получило бы 0.3.
Правило: для звеньев `engagement` (действие на мишень) поиск включает фармакологические и физиологические источники
(инструкции к одобренным препаратам не используются — только PubMed); если вещество одобрено для этого действия (ChEMBL:
показание и механизм действия совпадают со звеном), звено получает 0.9 с пометкой «установлено одобрением» без поиска.
Для прочих звеньев исключений нет: «все знают» без записи — это «не проверено».

Отступление при реализации (2026-11-03, `rules_v3.established_by_approval`): ChEMBL отдаёт мишени как идентификаторы, а не
названия, поэтому совпадение мишени со звеном кодом пока не проверяется; правило упрощено до «одобренный препарат (фаза 4) с
известным механизмом» и даёт уровень «умеренно» (5/6) вместо 0.9, с пометкой `<id>_established_by_approval`. Полная проверка —
когда граф знаний или справочник мишеней дадут названия.

### 9.3. Ключевые веса и их калибровка

Веса, которые меняют порядок гипотез, а не только баллы внутри него:

| Вес | Начальное значение | На что влияет |
|---|---|---|
| порог сильного опровержения | «против» ≥ 1.0 и больше двукратного «за» | что отсекается (эволюция требует не отсекать недоработанное) |
| положение «не проверено» на шкале звена | 3/6 | обмен «длинная смелая цепочка» против «короткой подкреплённой»; защита от раздутых гипотез |
| шкала размаха | 1/3, 2/3, 1 | самый сильный множитель в `V` |
| точность по числу участников | 4 полосы, неизвестное n — низшая | перевешивает ли большое РКИ несколько малых |
| место обзора и метаанализа на шкале дизайна | 4/7 и 6/7 | вклад обзоров |

Второго порядка: шкалы эффекта, сравнения и контекста, нормировка информативности 1.5. Все шкалы — равные шаги по уровням
(раздел 3); калибровка проверяет, не ломают ли они что-то, а не подбирает числа.

Калибровка без подгонки под исходы:
1. **Порядок** весов дизайна задан иерархией доказательности (как в GRADE): метаанализ ≥ РКИ > нерандомизированное >
   обсервационное > животные > клетки; меняются только числа, не порядок.
2. **Чувствительность**: каждый ключевой вес ±50%; на наборе примеров (раздел 7) считается устойчивость порядка (тау Кендалла
   с исходным порядком) и состав отсечения. Вес, от которого порядок прыгает, обсуждается отдельно; устойчивый — оставляется.
3. **Защиты**: раздутые гипотезы остаются в нижней четверти при любом весе из допустимого диапазона.
4. **Исходами испытаний** проверяются только веса, входящие в `P`, и только на свежей выборке с порогом, записанным до прогона.

Проверка чувствительности добавляется в раздел 7 как отдельная строка (бесплатно: пересчёт на сохранённых записях).

### 9.4. Реализуемость

Насколько трудно провести решающий эксперимент, заявленный в тексте:

| Часть | Значения | Источник |
|---|---|---|
| система | клетки < черви < мыши < люди | карточка |
| длительность | недели / месяцы / годы / десятилетия | карточка; реестр |
| цена | порядок величины в долларах (показатель `cost` v2) | класс эксперимента |
| размер выборки | планируемое число участников | реестр, текст |
| готовность вмешательства | одобренный препарат / известное вещество / новая молекула | ChEMBL (`path_to_human` v2) |
| измеримость исхода | проверенный исход / конечная точка, недостижимая за разумный срок | карточка |

Реализуемость — уровень профиля после `V` (решает при близких `V`), не множитель: дешёвый неинформативный эксперимент не
должен обгонять дорогой информативный. Явная невозможность (исход «продолжительность жизни человека») — пометка
«нереализуемо». Для гипотез из реестров почти не важна (испытание проведено); нужна для новых, сгенерированных гипотез.

### 9.5. Развёрнутый пример: левотироксин по правилам v3 (T = 2018-05)

Веса в примере — по первой версии раздела 3 (до перехода на равные шаги по уровням); вывод примера от этого не меняется,
пересчёт по шкалам уровней — при реализации правил.

Цепочка: L1 левотироксин → нормализует ТТГ; L2 недостаток гормона → ухудшение мышц; L3 лечение → улучшение силы и функции у
пожилых.

| Звено | Источник (из найденных аннотаций) | Вес |
|---|---|---|
| L2 | 2006, обсервационное, 57 против 37; слабость и сила поясов хуже (p < 0.05) | 0.5 × 0.97 × 0.8 × 1 × 0.6 = 0.23 «за» |
| L2 | 2009, Health ABC, обсервационное, 2290 человек 70–79 лет; риска проблем с мобильностью нет | 0.5 × 1 × 1 × 1 × 1 = 0.50 «против» |
| L3 | 2012, РКИ двойное слепое, 35 + 36; сила дыхательных мышц +11.5 (p = 0.041), бедра — нет | 1 × 0.84 × 0.5 × 1 × 0.6 = 0.25 «за» |
| L3 | 2013, «до и после», сердечная недостаточность (163 включены, сколько лечили — не указано); ходьба +58 м | 0.6 × 0.3 × 0.8 × 0.5 × 0.6 = 0.04 «за» |
| L3 | 2018, обзор, пересказ TRUST (≥ 65 лет, плацебо): нет улучшения силы мышц | 1 × 0.3 × 1 × 1 × 1 = 0.30 «против» (n в обзоре нет) |

L1 — 0.9 по правилу 9.2 (одобренное действие). L2 — спорно (~0.35). L3 — спорно (~0.35); с первичной статьёй TRUST (9.1)
«против» ~1.0 → отсечение. Без неё: P ≈ 0.9 × 0.35 × 0.35 ≈ 0.11; W = 0.5 (подтверждено только L1, эндокринная
физиология); альтернативы: A1 «мышечные жалобы — от возраста и болезней, а не от щитовидной железы» (опора Health ABC, a ≈ 0.5,
d = 1), A2 «повышенный ТТГ в старости приспособительный» (опору найти; a ≈ 0.5, d = 0.5) → I = 0.5; V ≈ 0.028.

## 10. Живая арена (идея пользователя, 2026-11-03)

Таблица гипотез не замораживается во времени: пул переоценивается по мере выхода новых статей и результатов, а эволюция
пополняет его новыми гипотезами. Подход v3 для этого подходит естественно, рейтинг Эло — нет:

| | Рейтинг Эло (турнир) | v3 |
|---|---|---|
| оценка | относительная, зависит от порядка поединков | абсолютная: звенья и записи самой гипотезы |
| новая статья | без новых поединков рейтинг не меняется | меняет силу только затронутых звеньев; правила пересчитываются бесплатно |
| почему изменилась | не видно | журнал: звено, уровень до и после, статья и дата |
| рост пула | поединков больше, чем гипотез | каждая гипотеза оценивается один раз |

Устройство:

1. **Пул**: замороженная карточка + версионный набор записей (когда добавлена, какой моделью извлечена).
2. **Наблюдение**: запросы утверждений (написанные моделью, прошедшие фильтр) становятся постоянными; раз в неделю новые
   статьи с прошлой проверки читаются проверяющим (только они); для гипотез со связанным испытанием — результаты в реестре.
3. **Переоценка**: правила по обновлённым записям; журнал изменений по гипотезе; отдельно — смены уровня звена и срабатывание
   ворот (мелкие сдвиги не выводятся).
4. **Эволюция**: новые гипотезы и улучшения старых по пометкам (слабое звено, улучшить эксперимент, назвать альтернативы);
   близкие варианты объединяются (proximity v2).
5. **Цена**: пересчёт правил и поиск бесплатны; платно только чтение новых статей (единицы на утверждение в неделю).

**Проспективная проверка.** Оценка, записанная с датой до результата, — чистый тест правдоподобия: модель не может знать исход,
срез по дате и проверка памяти (Б2) не нужны. Арена со временем сама становится растущим бенчмарком. Первый пул: идущие
испытания CT.gov с «само старение» среди состояний (подсчёт 2026-11-03: 673 интервенционных; у 367 первичное окончание в
ноябре 2026 — декабре 2028; набор идёт у 212, не начат у 104; поведенческие 145, лекарства и добавки 100, прочие 96, устройства
26). Оценки фиксируются в репозитории с хешем до результатов, как спецификации.

Риски: смена версий моделей (записи помечаются моделью, которая ответила); дрейф наблюдающих запросов (периодическая
перезапись); шум изменений (показываются смены уровня, не каждая запись).

## 14. v3.4: P как неопровергнутость, новизна, профиль «Фронтир» (2026-11-07)

Повод: внешний разбор v3.3 (Argon, шесть пунктов) и запрос пользователя контролировать новизну, особенно в эволюции, где
модель подтягивает гипотезу к известному результату. Решение пользователя: сделать бесплатные шаги 1–3, «Фронтир» — четвёртым
профилем, потомка со сдвигом к известному не исключать, только помечать. Определения: `specs/v34-frontier-2026-11-07.yaml`
(зафиксированы до расчёта), код: `rules_v32.evaluate(..., v34=True)`, `hyparena/card/novelty_v34.py`, проверка
`scripts/v34_check.py`.

- **P = неопровергнутость**: произведение по слотам R = (1 + cF) / (1 + cF + cA). Без данных «против» R = 1; первая скромная
  статья больше не снижает P (парадокс v3.3). Опору несёт только подтверждённость. На калибровке AUC 0.584 против 0.589 у v3.3.
- **Вид учитывается один раз** на звене исхода (дизайном), **точность постоянная 1/2** на звеньях до исхода.
- **Новизна N**: новый контекст < перенос < аналог < новое сочетание < новое звено; «неизвестно» без данных. Прошла правило
