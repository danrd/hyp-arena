# Инструкция для судьи гипотез · v1

Вы оцениваете исследовательские гипотезы о старении и здоровой продолжительности жизни. Для каждой пары ответьте, **какую гипотезу стоит исследовать первой и почему**.

К заданию приложены три файла.

- `judge_pairs.json` задаёт порядок сравнения и содержит `pair_id` и два `hypothesis_ids` для каждой пары.
- `judge_hypotheses_blind.json` содержит исходные формулировки, обоснования и заявленные эксперименты под ID из списка пар.
- `dossier.json` содержит общую подборку источников, наблюдения и записи по гипотезам. Связывайте записи по `hypothesis_id` и используйте общую дату среза T.

Обработайте все пары из списка в указанном порядке. Для каждой пары применяйте одни и те же критерии. Оценивайте исходные формулировки и заявленные эксперименты. Различайте результаты источников, интерпретации составителя и предположения авторов. Если для гипотезы нет записи досье или даты среза расходятся, сообщите о проблеме до оценки. Если досье описывает выполненный поиск, но данных мало, объясните, как это ограничивает выводы. Длина, стиль и предполагаемое авторство гипотез не влияют на оценку.

Оцените пару по четырём критериям.

1. **Научная обоснованность.** Насколько правдоподобен механизм с учётом данных за и против? Укажите решающий результат или слабое звено и объясните применимость данных к данному вмешательству, популяции и исходу. Отсутствие сведений, противоречащий результат и непроверенная экстраполяция имеют разный смысл. Регистрация описывает план. Биомаркер, функциональный исход и продолжительность жизни дают разные основания для вывода.
2. **Новизна.** Для каждой гипотезы назовите ближайшую найденную работу до T (PMID, DOI или ссылка), укажите, что в ней уже предложено или проверено, и сформулируйте конкретное отличие. Сравнивайте научный вопрос, в том числе вмешательство, популяцию, исход и механизм, если они определяют отличие. Работа с нулевым эффектом тоже может быть ближайшим предшественником. Если по досье ближайшую работу установить нельзя, прямо укажите это. Такую неопределённость учитывайте в сравнении новизны.
3. **Потенциальная польза.** Если гипотеза подтвердится, насколько значимым будет её вклад в здоровье или здоровую продолжительность жизни людей? Объясните, какая часть ожидаемой пользы следует из заявленного исхода и где требуется перенос на людей.
4. **Проверяемость.** Насколько осуществим и убедителен заявленный эксперимент? Объясните, какой результат помог бы отличить гипотезу от ближайшего конкурирующего объяснения и позволяет ли заявленный дизайн это сделать. Если эксперимент или существенная деталь отсутствуют, отметьте пробел. Оценивается эксперимент автора в представленном виде.

По каждому критерию укажите предпочтение: ID гипотезы, `tie` при сопоставимой оценке или `undetermined`, когда материала для сравнения недостаточно. Затем дайте общий вердикт по тем же правилам. Если критерии указывают в разные стороны, поясните, почему решающий критерий перевесил. Общий вердикт обоснуйте словами. Числовой суммы оценок нет. Для существенных утверждений указывайте доступный PMID, DOI или ссылку из досье. Для записи из досье также можно указать её `source_id`.

Верните один JSON-объект. В `judgements` дайте ровно один вердикт на каждый `pair_id` из задания. В `prior_work` дайте одну запись на каждую гипотезу из списка пар, даже если она встречается в нескольких сравнениях. В причинах по новизне опирайтесь на эти записи. Если ближайшая работа не установлена, оставьте `null` в полях `closest_work`, `already_known` и `difference` и укажите причину в `limitation`. Замените условные ID в примере фактическими.

```json
{
  "judgements": [
    {
      "pair_id": "P01",
      "criteria": {
        "grounding": {"preferred": "H01", "reason": "Обоснование"},
        "novelty": {"preferred": "undetermined", "reason": "Обоснование"},
        "benefit": {"preferred": "tie", "reason": "Обоснование"},
        "testability": {"preferred": "H01", "reason": "Обоснование"}
      },
      "overall": "H01",
      "decided_by": "grounding",
      "reason": "Почему этот вариант стоит исследовать первым"
    }
  ],
  "prior_work": [
    {"hypothesis_id": "H01", "closest_work": null, "already_known": null, "difference": null, "limitation": "Причина"},
    {"hypothesis_id": "H02", "closest_work": null, "already_known": null, "difference": null, "limitation": "Причина"}
  ]
}
```

`decided_by` — один из ключей `criteria` при выборе гипотезы и `null` при `tie` или `undetermined`. Все значения, кроме ключей, ID и служебных меток, пишите по-русски.
