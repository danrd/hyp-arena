# План проверки генерации и устойчивости оценки

Статус: проект экспериментов после пилота. Действующая версия метода — v3.11.
План связан со [спецификацией пилота](../../specs/evolution/generation-comparison-2026-11-16-pilot.yaml).
Материалы разбора и сверка отдельных гипотез хранятся в приватном архиве.

Гипотеза для проверки: проверка обязательной предпосылки до финализации улучшит научную обоснованность предложений BS при сохранении их проверяемости. Отдельная гипотеза: пропуск сведений о вмешательстве или эксперименте в некоторых случаях повышает оценки реализуемости. Для этих вопросов нужны разные сравнения.

## 1. Проверка оценщика на фиксированных входах

Сначала бесплатный прогон на минимальных контрпримерах и сохранённых карточках. В каждой паре менять только один аспект. Схема ожидаемых результатов записывается до расчёта.

| Проверка | Ожидаемое поведение |
| --- | --- |
| Скрыть название уже заданного вещества или смоделировать сбой справочника | Готовность не повышается. Различаются неуказанный агент, неудачное распознавание, известная доклиническая стадия и вмешательство, к которому фазы лекарств неприменимы. |
| Убрать размер выборки либо длительность | Появляется явный пробел. Удаление поля само по себе не улучшает итоговую рекомендацию о готовности проекта. Проверить также случай удаления мягкого требования к ресурсу. |
| Оставить тот же исход, но перенести эксперимент на другую модель | Отчёт указывает, какую предпосылку проверяет новая модель и какой исход остаётся за пределами эксперимента. План по этапам оценивается в пределах каждого заявленного этапа. |
| Перефразировать исход или изменить описание режима при том же научном вопросе | Прежняя работа сохраняется среди ближайших. Отдельно проверяется, что действительно различающиеся исходы, механизмы или режимы не сливаются. |
| Удалить отрицательную запись, оставить звено пустым, добавить неподтверждённое звено | Отчёт различает отсутствие данных и данные против. Отдельно проверяются покрытие и баланс. Действующее правило пустых звеньев уже было принято после [проверки](../../specs/scoring/empty-slots-2026-11-09.yaml), поэтому изменение профиля требует отдельного сравнения. |
| Добавить общую фразу об ослеплении или контроле | Засчитывается только указанная процедура, закрывающая конкретную угрозу. Для каждой отметки можно показать её опору в тексте эксперимента. |

Первый кандидат на локальную правку — ветка `readiness` для неразрешённого агента. На синтетической карточке и при пустом ответе справочника текущее значение равно 1,0. `feasibility` усредняет только известные компоненты, поэтому удаление большой выборки может повысить результат, а удаление малой — понизить. Сначала проверить, как отражать неопределённость в отчёте и профиле. Веса и пороги из материалов аудита требуют воспроизводимого сравнения.

Пересчёт оценщика проводить при замороженных карточках и записях. Для возможного изменения правил проверять профильные сдвиги, регрессии на калибровочном наборе и примеры корректной ранней доклиники. Пилотные гипотезы подходят для диагностики. Оценку обобщаемости проводить на отложенных примерах. Переход к новому правилу оформлять через профильный и сводный мануалы.

После получения исходных файлов добавился конкретный тест новизны. Близкий предшественник может присутствовать на промежуточном звене карточки, в то время как звено исхода остаётся пустым и итог получает высокий уровень новизны без ссылки на ближайшую работу. Сначала вывести кандидата в отдельное поле «ближайшая работа» с объяснением сопоставимости, затем проверить условия, при которых эта работа должна менять уровень. Так можно измерить полноту поиска предшественников отдельно от калибровки оценки и не приравнивать результаты разных исходов. Фиксировать исходные файлы по коммиту и хешам.

## 2. Проверка генератора на новых темах

Сравнить действующий BS с BS, в который добавлена **проверка одного критического контраргумента до фиксации гипотезы**. Для обеих веток сохранить исходные требования к дизайну, одинаковые тему, модель, дату среза, лимиты поиска и бюджета. Выделить ресурсы на проверку из общего лимита ветки. Вариант A можно сохранить как внешний ориентир, если хватает бюджета.

Проверка должна дать краткий результат: необходимая предпосылка, сильнейший аргумент против неё с источником, статус («есть прямые данные», «косвенные данные», «неизвестно», «есть противоречие») и действие («сохранить», «сузить тезис», «указать промежуточную проверку», «снять заявку»). Рассмотреть соответствие вмешательства, целевой системы, времени действия и точки измерения. Для новизны указывать ближайший аналог и проверяемую дельту по виду, режиму, исходу и причинному механизму. Перенос и новый механизм отражать раздельно. Условие обязательной синергии применимо лишь при заявке на синергию.

Сохранить и число отброшенных кандидатов, и число пригодных предложений на сопоставимый бюджет. Иначе фильтр может показать улучшение только потому, что пропускает меньше идей. У каждой гипотезы проверять критический разрыв по заранее заданным признакам: неопределённое вмешательство, несоответствие тезиса эксперименту, неподтверждённая обязательная предпосылка, ключевой источник прочитан в обратном направлении. Двум оценщикам дать одинаковые досье и скрытые условия. Разногласия хранить явно.

До запуска зафиксировать новые темы, размер выборки, правило прохождения и цену. Основной показатель — доля предложений с критическим разрывом. Проверяемость, новизна, тип новизны, выход пригодных гипотез на бюджет и общий приоритет исследования — отдельные метрики. В отчёте учитывать, что одни и те же гипотезы повторяются в парах. Единицы повторения для вывода — независимые генерации и темы. Текущие десять гипотез использовать для проверки процедуры, затем заморозить правило. Дополнительный этап судейства по новизне или новые веса проверять отдельным экспериментом.
